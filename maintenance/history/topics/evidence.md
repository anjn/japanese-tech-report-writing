# 根拠と不確実性

[現行のレビュー規範](../../../references/review.md) ／ [判断索引](../../decisions.md)

<a id="r01"></a>

### R01：推量を断定に変えない

適用段階：両方。

出典：論証の厳密さ、第1項。次は項目冒頭の原文抜粋であり、後続の条件・例文も維持対象とする。

> 推量・可能性・読者の疑念・反実仮想として書かれている文を、機械的に断定へ変えない。

- 目的：推敲で主張の確度を変えない。
- 採否案：採用。
- 理由：根拠のない緩和と、意味を持つ不確実性を区別する元の規範を残す。表現を具体化しても確度は維持する。

初回の合意は[第3回](../rounds.md#round-3)に記録。

<a id="r02"></a>

### R02：因果の説明

適用段階：両方。

出典：論証の厳密さ、第5項。

> 因果を主張するときは、その機構（なぜそうなるのか）を一文で示す。「AだとBになる」とだけ書いて理由を省略しない。悪い例：「手順で分けると変更が全体に波及する」。良い例：「各工程がデータを受け渡すための表現を共有してしまい、その表現を変えると全体に波及する」。

- 目的：因果関係を読者の推測に委ねない。
- 採否案：修正して採用。
- 理由：機構の説明だけで因果が証明されるわけではない。未確認の原因を補わず、一文という長さにも固定しない。
- 修正案：原因を述べるときは、因果を判断した根拠と、理解に必要な仕組みを示す。機構が未確認なら仮説として区別する。観測された差だけから原因を断定しない。詳しい説明は必要に応じて参照先へ分ける。

初回の合意は[第3回](../rounds.md#round-3)に記録。

<a id="r03"></a>

### R03：断定を強める推敲

適用段階：両方。

出典：冗長の排除、第12項。

> ためらいのある弱い述語（「有効な対策であり」など）で済ませない。本文内の根拠で確定していることは強く具体的に言い切る（「活用において必須であり」など）。ただし、不確実性・可能性・仮定・読者の疑念を表すための弱い述語は保持する。語調を整えるための意図的な緩和（「必須だと言ってもいい」など）は許す。

- 目的：不要なためらいを減らし、主張を明確にする。
- 採否案：修正して採用。
- 理由：「有効」と「必須」は強さだけでなく意味が異なる。必要性の根拠なしに置き換えない。
- 修正案：確認できた内容は具体的に述べ、根拠のない緩和を加えない。推敲によって、効果があるという主張を必要条件だという主張へ変えるなど、命題の意味や確度を変えない。

初回の合意は[第3回](../rounds.md#round-3)に記録。

<a id="r05"></a>

### R05：例の現実性を支える根拠

適用段階：両方。

出典：読者への誠実さ、第2項。

> その根拠は、著者の断定（「十分あり得る状況だ」）ではなく、読者自身の経験に訴える一般的事実や通説に求める（「この症状は珍しくないだろう」「〜という言い方もよく耳にする」）。

- 目的：説明用の例が現実に当てはまるか、読者が判断できるようにする。
- 採否案：修正して採用。
- 理由：経験への呼びかけや通説だけでは、頻度や現実性の根拠にならない。もっともらしい補足を作る誘因にもなる。
- 修正案：説明用に作った例と、確認された事例を区別する。現実に多い、一般的であるなどと主張する場合は根拠を示す。説明用の例に、根拠のない頻度や現実性の主張を付け加えない。

初回の合意は[第3回](../rounds.md#round-3)に記録。

<a id="b05"></a>

### B05：確認していない事実

適用段階：両方。

出典：読者への誠実さ、第3項、および手順書の書き方の検証に関する項目。

> 確認していないことを、確認したかのように滑らかに書かない。

> 検証していない手順は、検証していないと明記する。検証した範囲は、どこまで通したかを書く。

- 目的：文章の自然さによって、事実や検証範囲を誤認させない。
- 採否案：両項目とも採用。
- 理由：文章を整える際にも守る共通規範として残す。説明用の出力例と実際の実行結果も区別する。

初回の合意は[第9回](../rounds.md#round-9)に記録。

<a id="k04"></a>

### K04：主張と例の対応

適用段階：両方。

出典：論証の厳密さ、第7項。

> 主張は、挙げた例が実際にその全体を支えているかを確認する。例が主張の一部しか支えないなら、主張の範囲を例に合わせて狭める。

- 目的：一例からの過度な一般化を防ぐ。
- 採否案：採用。
- 理由：例を根拠として使う場合に適用する。別の根拠で確かめた主張を説明するための例について、例だけで全体を証明することまでは要求しない。根拠となる例と理解を助ける例を区別する。

初回の合意は[第12回](../rounds.md#round-12)に記録。

<a id="t01"></a>

### T01：保証や解決の断定

適用段階：両方。

出典：論証の厳密さ、第6項。

> 検出・保証・解決を「必ず」できるかのように書かない。条件付きで正確に述べる（「〜しやすい」「〜できることが多い」「〜が成り立つときに限り」）。

- 目的：根拠を超えた保証を避ける。
- 採否案：条件付き採用。
- 理由：「しやすい」「多い」への置換だけでは正確にならない。成立条件が確認できる場合は、その範囲で断定できる。
- 修正案：検出や保証を述べる際は、根拠と成立条件に合う確度で書く。根拠のない絶対表現を避ける一方、確認済みの性質を機械的に弱めない。頻度や傾向にも根拠を求める。R01、R03に統合して扱う。

初回の合意は[第15回](../rounds.md#round-15)に記録。

<a id="s03"></a>

### S03：弱い緩和と称賛

適用段階：レビュー時。

出典：LLM っぽい表現の禁止、「弱い緩和と称賛」。

> **弱い緩和と称賛**：「〜と言えるだろう」「〜かもしれない」（根拠なく主張を弱める場合だけ。推量・仮定・読者の疑念・作中人物の認識なら残す）、「非常に」「極めて」「大いに」（中身のない強調）

- 目的：確度を表さない緩和と、内容のない強調を減らす。
- 採否案：採用。
- 理由：R01、R03、A02に対応づけて残す。必要な推量は維持し、強調を具体化するための数値や評価を作らない。

初回の合意は[第17回](../rounds.md#round-17)に記録。
