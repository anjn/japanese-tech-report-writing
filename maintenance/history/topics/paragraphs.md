# 段落と説明の順序

[現行のレビュー規範](../../../references/review.md) ／ [判断索引](../../decisions.md)

<a id="m01"></a>

### M01：未知の概念を説明する順序

適用段階：両方。

出典：読み手の負荷の管理、第4項。

> 概念を初めて示す文では、読者が順に読んだだけで、まずその概念が何であるか（データ構造、手順、制約などの種類や地位）を読み取れる順序にする。その概念を既に知っている読者にだけ自然な性質・仕組み・制約を、種類の同定より前に置かない。前置すると、未習の読者は文を読み終えた時点で逆戻りしなければ核となる情報を見逃すか、理解が滞る。

- 目的：未知の概念について、性質を覚えてから正体を知る負担を避ける。
- 採否案：採用。
- 理由：初見の読者が説明を順に理解するための具体的な規範として残す。R04に従い、読者が既に知っている概念を毎回説明し直す必要はない。

初回の合意は[第7回](../rounds.md#round-7)に記録。

<a id="m04"></a>

### M04：並列の事実を一文にまとめること

適用段階：レビュー時。

出典：冗長の排除、第4項。

> 同じ論理的役割を持つ並列の事実は、文を分けて重ねず一文にまとめる。その事実群の論理的地位は文頭の語で示す（「当然、経理部の月次処理も顧客の支払いも〜」）。

- 目的：同じ構文の反復を減らし、事実間の関係を明確にする。
- 採否案：条件付き採用。
- 理由：項目数や条件が多い場合は、一文への圧縮が記憶の負担を増やす。「当然」という評価も根拠なく加えない。
- 修正案：並列の事実は、共通の関係が読み取れる形で示す。短く同じ条件なら一文にまとめ、項目が多い場合や個別の条件がある場合は、文を分けるか箇条書き・表を使う。必要な条件を省いて一文に圧縮しない。

初回の合意は[第7回](../rounds.md#round-7)に記録。

<a id="d01"></a>

### D01：対比する定義の文型

適用段階：レビュー時。

出典：段落と論証の構成、第8項。

> 同じ概念を二つの対象で対比定義するときは、両文の述部を同じ型にする。既出の説明の回収は文頭の枠に置き、定義そのものを「〜だと説明した」に埋め込まない。特徴の句は「」で切り出し、対比の接続を明示する。第二極について続ける属性は、主語を改めて名乗らず継承する。

- 目的：比較する観点と定義を読み取りやすくする。
- D01a（述部の型を揃える）：条件付き採用。比較しやすくなる場合に使い、意味の違いを型に合わせて消さない。
- D01b（定義を過去の説明への言及に埋め込まない）：採用。定義の内容を直接読めるようにする。
- D01c（文頭・引用符・主語省略の固定）：修正して採用。対象を見失わないことを優先し、必要なら主語を再掲する。引用符や配置は固定しない。
- 修正案：対比する定義は、比較の観点と対象が明確になるように書く。対応する表現は必要に応じて揃える。定義は直接示し、主語の省略や引用符の使用は、対応関係を読み取りやすくする場合に選ぶ。

初回の合意は[第10回](../rounds.md#round-10)に記録。

<a id="n01"></a>

### N01：段落の話題と冒頭

適用段階：両方。

出典：段落と論証の構成、第1・第2項。

> 一つの段落には一つのトピックだけを置く。場面の進行（調査、報告、検証、評価）が複数混ざった長い段落は、一歩ずつの段落に分割する。

> 段落の最初の文を読めば、その段落が何の話かわかるようにする。

- 目的：段落単位で話題と論理の流れを追えるようにする。
- N01a（一段落一話題）：採用。同じ話題の主張と根拠まで、別の作業段階という理由だけで機械的に分割しない。
- N01b（冒頭で話題を示す）：採用。定型的な予告文を足すのではなく、内容を述べる最初の文で話題を伝える。

初回の合意は[第13回](../rounds.md#round-13)に記録。

<a id="n02"></a>

### N02：隣接する節の統合

適用段階：レビュー時。

出典：冗長の排除、第2項。

> 隣接する節が同じことを別の角度で述べているなら、役割が重複している。片方に吸収して一つの節にまとめる。

- 目的：役割が重複する節を減らす。
- 採否案：条件付き採用。
- 理由：同じ対象でも、仕組みの説明と操作方法などでは利用目的が異なる。
- 修正案：隣接する節の対象と役割を確認し、同じ目的で同じ説明を繰り返している場合は統合する。理解、操作、参照など役割が異なる場合は分けてよい。対象が同じという理由だけでは統合しない。

初回の合意は[第13回](../rounds.md#round-13)に記録。

<a id="n04"></a>

### N04：読み進める間に保持する情報

適用段階：両方。

出典：読み手の負荷の管理、第1項。

> 読者が順読みで保持する情報は、一度に一段だけ増やす。箇所を削ったら残った言及を辿り、この文書のほかで使われなくなった主題は落とす。直前までの文の上に一段で足りる許可や読み方は直接書く。

- 目的：未説明の概念や文脈を覚え続ける負担と、編集後の不要な言及を減らす。
- N04a（一度に一段だけ増やす）：修正して採用。「一段」の数え方を固定せず、新しい概念の依存関係を整理し、必要な前提を説明してから進む。
- N04b（削除後の言及の点検）：条件付き採用。他で参照されなくても、その場の理解に必要なら残す。参照先を失った言及や、役割を失った説明を修正・削除する。
- N04c（許可や読み方を直接書く）：修正して採用。読者が必要とする条件や解釈を、曖昧な前置きや先送りで包まず、その場で具体的に示す。

初回の合意は[第13回](../rounds.md#round-13)に記録。

<a id="w04"></a>

### W04：接続表現の必須化

適用段階：レビュー時。

出典：段落と論証の構成、第3項。

> 段落の先頭では、前の段落との論理関係を接続表現で明示する（「であれば」「実際」「しかし」「この例自体からも」）。

- 目的：段落間の論理関係を追いやすくする。
- 採否案：条件付き採用。
- 理由：すべての段落に付けると定型的な接続詞が増える。接続詞だけでは、欠けている根拠や説明を補えない。
- 修正案：段落間の論理関係が曖昧な場合は、接続表現や具体的な説明で明示する。関係が自然に読み取れる場合は接続詞を足さない。論理が飛躍している場合は、接続詞でつながったように見せず、必要な説明を補う。

初回の合意は[第6回](../rounds.md#round-6)に記録。

<a id="s02"></a>

### S02：接続の型とリズム

適用段階：レビュー時。

出典：LLM っぽい表現の禁止、「接続の型」、および冗長の排除、最終項。

> **接続の型**：「〜において」「〜という側面から」「〜の観点から」（新情報なし）、「さらに」「また」「加えて」の連打

> 文章のリズムを作るための接続表現（「しかし一方で」など）は、冗長と見なさない。

- 目的：定型的な接続表現を減らしつつ、読みやすいつながりを保つ。
- S02a（新情報のない接続の型）：採用。関係を明確にする実質的な働きがある場合は残す。
- S02b（リズムなら冗長と見なさない）：条件付き採用。リズムという理由だけで残さず、論理関係と読みやすさに寄与するかで判断する。
- 修正案：接続表現は、関係や読み進める区切りを明確にする場合に残す。意味の重複や連打は整える。W04と統合する。

初回の合意は[第17回](../rounds.md#round-17)に記録。
