# 用語と対象の明確さ

[現行のレビュー規範](../../../references/review.md) ／ [判断索引](../../decisions.md)

<a id="r04"></a>

### R04：定義を置く位置

適用段階：両方。

出典：論証の厳密さ、第10項。

> 節の中心となる語は、その節以前に定義・対象範囲を述べてから使う。定義せず使い始めない。

- 目的：未知の語を読み手に推測させない。
- 採否案：条件付き採用。
- 理由：節の冒頭や初出で説明しても理解できる。既知の用語まで一律に定義する必要はなく、単独参照する節では再説明が役立つ場合もある。
- 修正案：未知の用語や独自の定義は、その語を理解していないと説明を追えなくなる前に示す。初出の文で説明してもよい。読者に既知の用語の説明は省き、独立して参照する節では必要に応じて定義や参照先を添える。

初回の合意は[第3回](../rounds.md#round-3)に記録。

<a id="t04"></a>

### T04：術語に見える一般表現

適用段階：レビュー時。

出典：視点と語り、第8項。

> 術語の響きを持つ語を、術語でない場面に流用しない（システムから人間までの連なりを「経路」と呼ぶ、など）。「届くまでの流れ」「あいだに何があるか」のように普通の言い方で書く。

- 目的：一般的な説明を、定義済みの専門概念と誤認させない。
- 採否案：条件付き採用。
- 理由：「経路」のように一般語としても使える語を一律に避ける必要はない。
- 修正案：専門的な意味と一般的な意味を取り違えやすい箇所では、意味を明示するか平易な言い方に直す。語の響きだけで禁止せず、文脈上の曖昧さで判断する。

初回の合意は[第15回](../rounds.md#round-15)に記録。

<a id="m02"></a>

### M02：抽象語の指す対象

適用段階：レビュー時。

出典：読み手の負荷の管理、第3項。

> 抽象的な言い回しの指す内容が文脈から一意に決まらないときは、可能なときは丸括弧による同格挿入でその場で特定し、できるだけ読者に前を読み返させない。

- 目的：指示対象を探す読み返しを減らす。
- 採否案：修正して採用。
- 理由：括弧は有効な方法だが、抽象語を具体語に置き換えるほうが読みやすい場合もある。
- 修正案：抽象語や指示語の対象が曖昧なら、具体的な名称に置き換えるか、その場で短く補足する。括弧、別の文などは説明の長さに応じて選び、対象を特定するための読み返しを減らす。

初回の合意は[第7回](../rounds.md#round-7)に記録。

<a id="m05"></a>

### M05：説明を名称に置き換えること

適用段階：両方。

出典：冗長の排除、第10項。

> 文脈を最短で読み手と共有できる文章にする。導出を一歩ずつ展開しなくても伝わるなら、構造に名前を与えて言い切る。

- 目的：既知の説明を繰り返さず、簡潔に文脈を共有する。
- 採否案：条件付き採用。
- 理由：名前が未知なら、命名だけでは説明にならない。使い捨ての独自用語が増えると記憶の負担になる。
- 修正案：読者に既知の概念は、慣用される名称を使って簡潔に説明する。独自の名称を付ける場合は、その意味を説明し、以後の参照に役立つ場合に限る。名前を付けることで、必要な仕組みや根拠の説明を省かない。

初回の合意は[第7回](../rounds.md#round-7)に記録。

<a id="d05"></a>

### D05：人物名の表記

適用段階：レビュー時。

出典：視点と語り、第7項。

> 人物そのものに言及するときは原綴りで書く（Lehman、Bainbridge）。ただし、歴史上の人物や、人名を冠した概念を定着名で紹介するときは、日本語で通用しているカタカナの通称を使う。

- 目的：人物と概念の名称を、識別できる表記で示す。
- 採否案：修正して採用。
- 理由：原綴りの一律指定より、分野の慣用、既存文書の表記、検索や文献との照合の必要性に合わせる。
- 修正案：人物名や人名を含む概念名は、分野で定着した表記と文書内の一貫性を優先する。人物の識別や出典との照合に必要なら原綴りを添える。

初回の合意は[第10回](../rounds.md#round-10)に記録。

<a id="x04"></a>

### X04：まだ導入していない対象への言及

適用段階：レビュー時。

出典：冗長の排除、第11項。

> 本文でまだ導入していない概念や文書名を、先回りして持ち出さない。

- 目的：説明のない名前を覚えたまま読み進める負担を避ける。
- 採否案：条件付き採用。
- 理由：概要や案内で先に名前を示すことはある。知らない対象の理解を要求しないことが重要。
- 修正案：未知の概念や文書名を使う際は、その場の理解に必要な説明や参照先を添える。概要や案内での先出しは認めるが、意味を知らないまま後続の論理を追わせない。R04、D04に統合する。

初回の合意は[第18回](../rounds.md#round-18)に記録。

<a id="w02"></a>

### W02：日本語訳と原語

適用段階：両方。

出典：英語の用語、識別子、コード、第1項。

> 英語の用語は、初出で一度だけ説明し、以降は同じ表記で通す。日本語訳と英語を併用しない。

- 目的：表記の揺れと重複説明を減らす。
- 採否案：条件付き採用。
- 理由：原語は検索や仕様との照合に役立つ。一律に併記を禁じない。説明の要否と再掲はR04に合わせる。
- 修正案：同じ概念には同じ用語を使う。読者に未知の語は初出で説明し、検索や照合に必要なら原語を併記する。以降は基本の表記を決めて通し、独立して参照する節では必要に応じて説明や原語を再掲する。

初回の合意は[第6回](../rounds.md#round-6)に記録。

<a id="w03"></a>

### W03：固有名と識別子の省略

適用段階：両方。

出典：読み手の負荷の管理、第2項。

> 後で参照する必要のない固有名（ファイル名、関数名、識別子）を出さない。「仕様書」「金額計算のユーティリティ」のような一般的な言い方で済ませる。

- 目的：覚える必要のない名前を減らす。
- 採否案：条件付き採用。
- 理由：一度しか登場しなくても、対象の特定、検索、検証に必要な名前はある。
- 修正案：理解や利用に寄与しない固有名は省く。対象の区別、実行、検索、検証、追跡に必要な名称や識別子は正確に残す。説明用の例では、議論に関係しない名前を増やさない。

初回の合意は[第6回](../rounds.md#round-6)に記録。

<a id="v03"></a>

### V03：用語の具体性と慣用

適用段階：両方。

出典：視点と語り、第4〜第6項。

> 対象を指す語は具体的に選ぶ。「AI」「ツール」のような広い語でぼかさない。

> 章や節で定式化・術語（K、契約、不変条件など）を導入したら、以後はその語で通す。「文脈」「ツール」「AI」のような曖昧語に後退しない（定式化する前の導入語として「文脈」などを使うのはよい）。

> 術語・訳語は、その分野で慣用されている語を選ぶ（プッシュ通知は「配送」ではなく「配信」、など）。意味の近い漢語を一般語の感覚で充てない。

- 目的：対象の特定と用語の一貫性を保ち、不適切な訳語を避ける。
- V03a（具体的な対象）：採用。対象を特定する必要がある箇所に適用する。一般的な種類について説明する場合にまで製品名などを要求しない。
- V03b（導入した術語を維持）：採用。W02、K03に統合して扱う。
- V03c（分野の慣用語）：採用。原文の例を全分野共通の禁止語一覧にはせず、対象分野での意味に合わせる。

初回の合意は[第14回](../rounds.md#round-14)に記録。

<a id="z05"></a>

### Z05：単位・略語と識別子

適用段階：両方。

出典：英語の用語、識別子、コード。

> 数値の単位、略語（BF16、mAP など）は、読者の前提に含まれるものは説明しない。含まれないものは、初出で一文だけ説明する。

出典：英語の用語、識別子、コード。

> 識別子、パス、オプション名は、本文では読者が実行または参照するものだけを書く。後で参照しないものは、一般的な言い方に置き換える。

- 採否案・適用方針：条件付き採用・既存項目へ統合。単位・略語の説明はR04・W02に合わせ、読者の前提に応じて行う。一文という長さは固定せず、数値に必要な単位は省かない。識別子はW03に合わせ、実行・検索・追跡に必要なら残す。

初回の合意は[第19回](../rounds.md#round-19)に記録。
