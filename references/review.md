# 技術文書のレビュー規範

対象文書の目的と読者を確認し、関係する規範を使う。内容と構成、読み手の負荷、日本語表現の順に点検する。全項目を指摘として列挙する必要はない。

指摘は、どの誤読や負担を減らすか説明できるものに絞る。好みだけで書き換えず、問題のない箇所は維持する。不足する事実や意図は確認し、補作しない。レビュー依頼には重要な指摘と修正案を、書き換え依頼には修正文を中心に返す。

## 目的と情報の過不足

- 目的、読者、利用場面に必要な情報が揃っているか確認する。結論が未確定なら、問いと判明している範囲を示す。資料で分かる事項を質問し直さず、正確さや構成、実行可否に関わる不足を確認する。
- 理解・判断・実行・参照・後日の追跡に役立つ情報を残す。役立つ可能性だけを理由に詳細を積み上げない。一部の読者だけに必要な情報は、削除より移動が適切な場合もある。
- 失敗の経緯は、原因究明、判断の追跡、再試行の回避に必要な範囲で残す。
- 未実施項目は、目的や結果の適用範囲に関わるものを示す。検証範囲や進捗の確認が目的なら一覧にしてよいが、想像できる未実施事項を際限なく列挙しない。

## 根拠と不確実性

- 事実、推定、提案、仮定を区別する。未確認の内容を確認済みとして書かない。検証した環境と範囲、未検証の手順を明示し、説明用の出力例と実行結果を区別する。
- 根拠のない緩和は減らすが、推量や可能性を機械的に断定へ変えない。確認した事実も理由なく弱めない。「有効」を「必須」に変えるなど、意味や確度が変わる推敲をしない。
- 因果を述べるときは、その判断の根拠と理解に必要な仕組みを示す。機構が未確認なら仮説として扱い、観測された差だけから原因を断定しない。
- 保証や解決は、根拠と成立条件に合う範囲で述べる。「必ず」を「しやすい」に変えるだけで済ませず、頻度や傾向にも根拠を求める。
- 根拠として使う例が主張を支える範囲を確認する。別の根拠で確かめた主張を説明する例に、主張全体の証明まで要求しない。

## 概念と論理の整合

- 異なる対象や複数の要因を一つにまとめて混同しない。未確認の要因を網羅的に作り足すこともしない。
- 上位概念でまとめる際は共通点を示し、必要な違いを残す。同じ分類に属することを、同一であることと取り違えない。
- 文書全体で定義、分類、用語を一致させる。表現が異なるだけで矛盾とはせず、意味や責任分担が変わっていないかを見る。
- 譲歩では、認める事実・条件と認めない結論を区別する。後で否定する解釈を事実として断定せず、根拠のない通説や読者の反応に帰属させない。
- 否定・限定の対象と理由を明確にする。直前に示した根拠は重ねなくてよい。反実仮想は事実と区別する。限定が結論にどう影響するか伝われば、限界や未解明の点で節を終えてよい。
- 起こりやすく重要な誤解は訂正する。不要な否定対比を増やさず、通常は正しい内容と理由を直接述べる。

## 構成と見出し

- 判断用の文書では結論と重要な条件を先に示し、根拠や代替解釈を続ける。技術解説では、理解に必要な前提や例から進めてもよい。演出のために結論や条件を伏せない。
- レポートは概要、根拠、必要な再現手順を基本とする。概要には目的、結論、主要結果、重要な制約を示す。数値は判断に必要な場合に、単位と比較対象を添える。
- 根拠には、判断に影響する反証や限界も含める。作業した順序や固定の章立てに合わせるために、説明を分断しない。
- 題名と見出しは、対象・問い・結果・操作を特定できるものにする。結論や操作名を示してよいが、条件を外した過大な断定や、内容の分からない決め台詞は避ける。
- 副題は範囲・条件・方法など、識別に役立つ情報を補う場合に使う。名詞句、疑問形、断定形などの形式は固定しない。

## 段落と説明の順序

- 一段落を一つの話題にまとめ、内容を述べる最初の文で話題を伝える。同じ話題の主張と根拠を機械的に分割しない。
- 未知の概念は、何であるかを示してから性質・仕組み・制約を説明する。必要な前提を先に説明し、未説明の情報を覚え続けさせない。
- 対比する定義は、対象と比較軸を明確にする。対応する表現は必要に応じて揃えるが、意味の違いを型に合わせて消さない。定義は直接示し、主語や引用符は分かりやすさに応じて使う。
- 隣接する節は、対象だけでなく役割も重複するときに統合する。仕組みの説明と操作方法など、用途が異なる節は分けてよい。
- 並列の事実は、短く条件が同じなら一文にまとめる。項目や条件が多ければ文・箇条書き・表に分け、必要な条件を圧縮で失わない。
- 接続表現は論理関係や区切りを明確にする場合に使う。連打や意味の重複を減らし、説明の欠落を接続詞で覆わない。

## 重複と参照の負担

- 冗長さを文字数や文数だけで判断しない。短縮により対象、操作、因果、条件を推測させるなら、必要な長さを残す。
- 同じ役割の箇所で同じ主張を言い換えない。概要、独立して参照する節、操作時の確認では必要な再掲を認める。新しい命題や適用条件、並列関係を示す語の反復まで削らない。
- 表の全数値を本文で読み上げず、差や理由を説明する。その場の比較に必要な基準値や主要結果は残し、再掲値の単位・条件も一致させる。
- 操作の理由の説明と実行時の確認は両方残してよい。短い説明の単なる言い換えは省き、長い説明の要点整理は残す。
- 前提は必要になる前に、局所的な補足は近くに置く。詳細は後段や別資料へ分けても、誤読を防ぐ条件は後回しにしない。
- 参照先は具体的に示し、案内した内容が実際にあるか確認する。構成変更・削除後も、参照先を失った言及や役割のない説明を点検する。

## 例と媒体間の対応

- 説明用に作成・単純化した例と、確認された事例を区別する。省いた条件が適用範囲に影響するなら示す。「よくある」など現実性や頻度を主張するなら根拠を添える。
- 例を追加する際は、新たに示す条件や性質を明確にする。違いが自明なら前置きは不要。同じ説明を繰り返すだけの例は増やさない。
- 例に必要な具体性は残す。時刻、HTTPステータス、固有名などを情報の種類だけで削らず、根拠や追跡に必要かで判断する。
- 図・表・コードの役割を分け、同じ対象なら名称・値・条件を揃える。別例なら違いを示し、一方で確認した性質を他方へ無条件に当てはめない。
- 指示語の対象と置換の方向を明確にする。「Aの代わりにB」なら、採用する側はBであることが伝わるようにする。

## 手順と実行条件

- 目的、実行場所、操作・入力、成功判定をその場で確認できるようにする。共通事項はまとめ、切り替わる箇所で明示する。操作を読み上げ直すだけの説明は省いてよいが、目的・選択条件・影響は推測に任せない。
- 開始可否に関わる環境・権限は冒頭に、操作固有の注意は直前に置く。重要な注意は必要に応じて再掲する。
- 順序のある操作には番号を付け、準備と本題の開始位置を分かるようにする。順序のない確認項目まで番号付き手順にしない。
- 作業ディレクトリと必要なパスを示す。配置の関係が重要ならツリーを使い、既存ファイルと生成物を区別する。
- 置換箇所と値の決め方を実行前に示す。そのまま実行できる例と区別し、秘密情報の実値を記入例にしない。
- 期待値や状態は操作の近くに示す。大きな表を参照するなら、照合する項目を指定する。失敗時は必要な確認先や次の行動を示し、原因や出力を作らない。
- 必須・禁止・推奨を区別する。語調を和らげるために禁止や停止条件を曖昧にしない。影響は発生条件・対象・対応とともに示し、根拠のない危険を積み上げない。

## 図表とコードの提示

- 表は正確な値や条件の比較・参照に、グラフは傾向・分布・時間変化に使う。項目数や一文で書けるかだけで選ばない。
- 表の比較軸・見出し・単位を揃える。図表に読み取りに必要な条件を添え、詳細を別の節へ置くなら参照先を示す。行数は固定しない。
- 長いコードは媒体に応じて付録、別ファイル、折りたたみなどへ分け、入手先と実行方法を示す。その場で必要な操作や短いコードまで分離しない。

## 用語と対象の明確さ

- 同じ概念には同じ名称を使い、分野の慣用に合う術語・訳語を選ぶ。対象の特定が必要な箇所を「AI」「ツール」などでぼかさない。一般論にまで製品名を要求しない。
- 未知の用語・略語や独自の定義は、理解に必要になる前に説明する。初出で説明してもよい。既知の語の説明は省き、独立参照する節では必要に応じて再掲する。
- 検索・照合に必要なら原語を併記する。人物名も慣用と文書内の一貫性を優先し、必要なら原綴りを添える。必要な単位は省かない。
- 対象の区別、実行、検索、検証、追跡に必要な識別子は正確に残す。一度しか使わなくても省かない。
- 抽象語や指示語の対象が曖昧なら、具体語に置き換えるか、その場で補足する。専門的意味と一般的意味が混同される場合は説明する。
- 慣用の名称で簡潔に説明してよい。独自の名称は意味を説明し、後の参照に役立つ場合に限る。命名によって必要な仕組みや根拠を省かない。

## 空疎な表現と不自然な比喩

- 内容のない予告、直前の言い換えだけの総括、姿勢だけの宣言を省く。範囲や読む順序の案内、長い説明の要点整理は残す。
- 「重要」「多角的」「正面から扱う」「掘り下げる」などで説明を済ませず、対象・観点・行為を示す。「効く」「筋がいい」も効果や理由を具体化する。単語だけを禁止せず、情報を加えているかで判断する。
- 情報や関係を加えないつなぎと根拠のない評価は省く。判断に必要な評価は基準を示して残す。問いや提案を直接述べ、不要な自己弁護は省くが、判断記録の立場・責任範囲・選択理由は残す。
- 不自然な直訳や擬人化は、文脈と分野の慣用を確かめ、処理や観測できる事実に直す。新しい性質や事実を足さない。意味が不明なら確認し、言い換えにくいだけで削除しない。
- 「サーバーが応答を返す」のように明確な無生物主語は維持する。字義どおりの動作を想像できるという理由だけで比喩を排除しない。

## 文体・語り・強調

- 指定・提出先の書式・既存文書の文体に合わせ、指定がなければ「です・ます」調を基本とする。本文は統一するが、引用・コード・見出し・表まで同じ文末にしない。実際の引用を勝手に直さない。
- 「難しいです」「多いです」などを一律に禁止しない。必要な対象や比較条件と、前後の関係が伝わるか確認する。
- 行為者や役割の区別が必要なら明記する。結果や対象が主題なら受動態も使える。未知の主体は作らない。
- 不要な呼びかけ、架空の問答、読者の感情の決めつけを避ける。実用的なFAQや演習、自然な案内は認める。説明に関係しない人物設定を加えず、年次などで能力を決めつけない。
- 内容を伝えない溜め・決め台詞・感嘆を重ねない。短文・疑問文・体言止めは、論点や区切りを明確にする場合に使える。
- 強調は要点や操作上の注意に絞る。回数は固定せず、重要箇所を見分けられるかで判断する。見出し・段落・順序で整理できる内容を太字だけで処理しない。

## 修正後の確認

数値、単位、対象、条件、確度、用語、参照先を確認する。短縮や具体化によって、必要な説明や意味が失われていないかを見直す。

## 表現を見直す具体例

以下は説明用の例。実際の文脈で意味と根拠を確かめて使い、置換辞書として適用しない。

| 点検対象 | 元の表現 | 見直し方 |
|---|---|---|
| 内容のない予告 | 本章では理論を正面から扱います。 | 姿勢の修飾を省く。範囲の案内が必要なら「この節では適用条件を説明します」など、実際の内容を書く。 |
| 不確実性 | 提示し続けているかもしれません。 | 「提示し続けている可能性があります」など、確度を維持して整える。確認せず「提示し続けています」にしない。 |
| 主張の強化 | 有効な対策です。 | 効果の内容を確認して具体化する。「必須です」へ変えるには、必要条件だという別の根拠が要る。 |
| 不自然な直訳 | この問いは開かれています。 | 未解決という意味なら「この問いにはまだ答えが出ていません」とする。 |
| 所在を表す比喩 | この情報は残差ストリームに住んでいます。 | 所在が確認されているなら「残差ストリームに含まれています」とする。 |
| 意思・認識の擬人化 | モデルは文体を知っています。 | 何を観測したか確認する。出力の一貫性を確認したのであれば、その事実を書く。未確認なら作り足さない。 |
| 曖昧な効果 | この設定が効きます。 | 実際に変化した動作や指標を書く。数値がなければ捏造せず、分かっている範囲を示す。 |
| 意味を変える具体化 | 推敲の軸が露出します。 | 評価基準の明確化を意味するなら「推敲で使う評価基準が明確になります」とする。「線形に取り出せる」など新しい性質を加えない。 |
| 否定対象の曖昧さ | 何もかもが解決するわけではありません。 | 残る問題や適用外の条件を具体的に示す。分からない問題を列挙しない。 |
| 慣用句の不自然な変形 | 知識を体に入れます。 | 習得を指すなら「知識を身につけます」とする。 |

「ベクトルが選好を運ぶ」のような表現も、何を表すかで修正が異なる。選好の表現なのか、処理中の情報伝達なのかを確かめ、意味を取り違えずに具体化する。
